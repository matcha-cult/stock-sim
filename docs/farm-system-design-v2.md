# 灵田系统 V2 — 网格化 + 杂交 + 变异

> 基于 V1 的完全重构。V1 是线性田块（6 个 slot），V2 改为 4×4 网格，引入相邻、杂交、变异三大机制。
>
> **注意**：V1 未投产，无存量用户，直接删除 V1 表结构重建。

## 一、核心变化概览

| 维度 | V1 | V2 |
| ---- | -- | -- |
| 灵田形态 | 线性田块（6 个 slot） | 网格（4×4 → 5×4 → 6×4） |
| 最小单位 | plot（slot_index） | cell（row, col） |
| 田块升级 | 每块独立升 tier | 整体灵田等级 → 解锁列数扩展 |
| 杂交 | 手动配方培育（消耗灵材+灵石） | 种植时四方向相邻自动触发 |
| 变异 | 无 | 种植时小概率随机变异 |
| 品质 | 无 | 三档（优质/普通/劣质） |
| 相邻概念 | 无 | 杂交四方向（上下左右）、装饰物八方向（含对角线） |

---

## 二、网格数据结构

### 2.1 网格规格

- 初始：4 行 × 4 列 = 16 格
- 第一次扩展：5 行 × 4 列 = 20 格（新增第 5 行）
- 第二次扩展：6 行 × 4 列 = 24 格（新增第 6 行）

**扩展方式**：每次增加一行（不是列），保持 4 列不变。移动端竖屏布局下，向下延伸比向右延伸更自然，不会导致横向溢出或需要横向滚动。

**坐标系统**：(row, col)，row ∈ [0, maxRow-1]，col ∈ [0, 3]。

### 2.2 数据库表

farm_cell 表结构详见第七章（7.1 节）。

### 2.3 解锁规则

- 灵田等级 1：4×4（row 0~3 全部可用）
- 灵田等级 2：5×4（row 4 解锁，需购买）
- 灵田等级 3：6×4（row 5 解锁，需购买）

每个格子独立购买解锁，但扩展是按行顺序的：必须解锁 row=4 的所有列后，才能购买 row=5。

### 2.4 相邻定义

**杂交系统**使用四方向（上、下、左、右），**装饰物系统**使用八方向（含对角线）。

#### 2.4.1 杂交相邻（四方向）

杂交判定时，每个格子的相邻格子包括：上、下、左、右共四个方向。

计算相邻格子时，对每个方向偏移量（dr, dc），检查目标坐标是否在网格范围内：
- row + dr >= 0 且 row + dr < maxRow
- col + dc >= 0 且 col + dc < 4

边界格子（如边缘）只有 2~3 个有效邻居。

**设计理由**：四方向限制使杂交布局更具策略性，避免八方向导致稀有配方过于容易触发。

#### 2.4.2 装饰物相邻（八方向）

装饰物效果范围使用八方向（含对角线），包括：上、下、左、右、左上、右上、左下、右下。

计算方式与杂交相同，但方向数量为 8 个。

**设计理由**：装饰物是辅助效果，不涉及配方匹配，八方向增加布局灵活性。

## 三、杂交系统

### 3.1 核心理念

V2 的杂交是**种植时自动触发**的：当玩家在某格种下**基础作物**（如灵稻、灵果、灵花等）时，系统立即检查其**四方向相邻格子**（上下左右），收集所有**处于非成熟阶段**的相邻作物，按**物种集合**匹配杂交配方。杂交种子能否实际发放取决于作物是否发生金光变（详见 3.6 节）。

**关键设计**：
- 杂交匹配依据是**物种（crop_id）**，不是灵根元素
- 灵根作物（灵根·金/木/水/火/土）是可选参与者，不是必须
- 每种基础作物有独立的杂交配方体系

### 3.2 杂交配方表

杂交有**固定公式**，每种组合有确定的产物。配方结构为：**基础作物 + 所需相邻作物集合 → 产物**。

**灵稻系配方示例**：

| 配方名称 | 基础作物 | 所需相邻作物 | 产物 | 描述 |
|---------|----------|--------------|------|------|
| 水灵稻 | 灵稻 | [灵根·水] | 水灵稻 | 灵稻受水灵根滋润，化为水灵稻 |
| 碧粳稻 | 灵稻 | [灵根·水, 灵根·木] | 碧粳稻 | 水木相生，孕育碧粳稻 |
| 壤金稻 | 灵稻 | [灵根·土, 灵根·金] | 壤金稻 | 土生金，凝练壤金稻 |
| 七星稻 | 灵稻 | [碧粳稻, 青炎稻, 炎土稻, 壤金稻, 玄冰稻] 任意4种 | 七星稻 | 四象汇聚，孕育七星稻 |

**配方结构（JSON）**：
```json
{
  "baseCropId": "rice_basic",
  "requiredCrops": ["spirit_root_water", "spirit_root_wood"],
  "resultCropId": "bi_jing_rice",
  "resultSeedItemId": "seed_bi_jing_rice"
}
```

**部分满足配方（JSON）**：
```json
{
  "baseCropId": "rice_basic",
  "requiredCrops": ["bi_jing_rice", "yan_huo_rice", "yan_tu_rice", "jin_sui_rice", "xuan_bing_rice"],
  "minRequired": 4,
  "resultCropId": "qi_xing_rice",
  "resultSeedItemId": "seed_qi_xing_rice"
}
```

**设计说明**：
- 基础作物（如灵稻、灵果、灵花）各有独立的配方体系
- 配方匹配依据是物种（crop_id），不是灵根元素
- 灵根作物（灵根·金/木/水/火/土）是特殊作物，可参与多种配方
- 所需相邻作物是集合关系，必须全部满足才能匹配
- 每种杂交产物是独立的作物类型，有自己的生长周期、产量、售价、稀有度

### 3.3 杂交触发机制

**触发时机**：
- 玩家种植作物时（plantCrop API 调用时）
- 立即检查新种作物的四方向相邻格子

**判定条件**：
1. 新种作物是**基础作物**（有杂交配方的作物）
2. 新种作物的四方向相邻格子中有**非成熟作物**
3. 收集所有非成熟相邻作物的 crop_id 集合
4. 匹配配方：基础作物 + requiredCrops ⊆ 相邻作物集合
5. **多配方匹配时**，优先产物稀有度（rarity）高的配方

**杂交结果**：

- 判定成功：记录待发放杂交种子（第 1 代），作物进入第二阶段后、且发生金光变时实际发放（详见 3.6、3.8 节）
- 判定失败：无产物

**多配方优先级**：
- 匹配多个配方时，按产物作物的 `rarity` 字段降序排序
- 稀有度相同则按配方定义的 `sortOrder` 排序
- 最终选择优先级最高的配方

**设计说明**：
- 种植时判定比成熟时判定更简单：只需检查一次，不需要扫描全场
- 四方向限制使杂交布局更具策略性，避免稀有配方过于容易触发
- 发放种子到种子袋，简单可控，给玩家选择权
- 相邻作物在非成熟阶段即可参与杂交，降低杂交门槛
- 灵根作物不消耗，可重复参与多次杂交

### 3.4 杂交触发逻辑

种植作物时，系统立即执行以下步骤：

1. 检查新种作物是否是**基础作物**（有杂交配方的作物）
2. 获取新种作物的四方向相邻格子
3. 筛选出**非成熟阶段**的相邻作物（还在生长中）
4. 收集所有符合条件的相邻作物的 `crop_id` 集合
5. 查找匹配的杂交配方：
   - 配方的 `baseCropId` 等于新种作物的 `cropId`
   - 配方的 `requiredCrops` 是相邻作物集合的子集
6. 如果匹配多个配方，按产物 `rarity` 降序排序，选择优先级最高的
7. 如果触发，**记录待发放杂交种子**到 farm_cell.pending_hybrid_seed（不立即发放，详见 3.8 节）

### 3.5 杂交产物处理

杂交判定成功后，杂交种子进入"待发放"状态（详见 3.8 节）：

- 种植时判定成功，但种子不会立即发放
- 收获时，**金光变或优质品质**满足任一条件，种子实际发放到种子袋
- 如果萌芽阶段铲除，已判定的杂交会被撤销
- 如果收获时既非金光变也非优质，即使有 pending_hybrid_seed 也不会发放

### 3.6 金光变与杂交种子发放

**核心理念**：金光变或优质品质是杂交种子发放的必要条件，因为这两种情况才能留种，这是杂交的生物学基础。

**判定条件**：
- ~~原条件：相邻作物必须是金光变才能参与杂交~~
- ~~原条件：杂交种子发放要求新种作物发生金光变~~
- **新条件：杂交触发不要求相邻作物是金光变，杂交种子发放要求新种作物金光变或优质品质**

**触发流程**：
1. 种植时检查新种作物是否是基础作物
2. 检查四方向相邻格子，收集非成熟阶段的相邻作物集合
3. 匹配配方（基础作物 + requiredCrops ⊆ 相邻作物集合）
4. 多配方匹配时，优先产物 rarity 高的
5. 杂交判定成功，记录 `pending_hybrid_seed`
6. 收获时，检查是否满足发放条件（金光变或优质品质）
7. **金光变或优质**：发放杂交种子到种子袋
8. **非金光变且非优质**：不发放杂交种子

**设计说明**：
- 杂交触发门槛降低：相邻作物在非成熟阶段即可参与，不需要等成熟
- 金光变或优质品质都是杂交种子发放的必要条件，保持"好品质才能留种"的核心设定
- 玩家追求金光变或优质品质才能获得杂交种子，但触发时机更灵活
- 增加策略深度：玩家可以在相邻作物生长中时就种植新作物触发杂交，但仍需好品质才能获得种子

### 3.7 杂交种子代数限制（三代规则）

**核心理念**：杂交产出的种子有代数追踪，三代内可正常育种，三代后除非金光变否则枯萎时颗粒无收。

**代数定义**：
| 代数 | 来源 | 说明 |
|------|------|------|
| 第 0 代 | 商店购买 / 初始种子 | 基础种子，无代数限制 |
| 第 1 代 | 杂交直接产出 | 两个不同灵根金光变杂交产出 |
| 第 2 代 | 第 1 代种植后收获产出 | 第 1 代作物收获时返还的种子 |
| 第 3 代 | 第 2 代种植后收获产出 | 第 2 代作物收获时返还的种子 |
| 第 4 代+ | 第 3 代种植后 | **除非金光变，否则枯萎时颗粒无收** |

**枯萎颗粒无收规则**：
- 第 4 代及以上的作物（非金光变），枯萎时：
  - 不返还种子（即使是优质品质也不返还）
  - 灵材正常收获（产量、品质不受影响）
  - 只是没有种子产出
- 金光变例外：即使是第 100 代，金光变仍可留种

**数据存储**：
- 种子袋表新增 `generation` 字段（默认 0）
- 商店种子、初始种子：`generation = 0`
- 杂交产出种子：`generation = 1`
- 收获产出种子：`generation = parent.generation + 1`

**UI 展示**：
- 种子袋显示代数标识（如"第 2 代"或"G2"）
- 第 4 代及以上的种子用特殊颜色标记（如红色），提示"枯萎后无法留种"

**设计说明**：
- 三代限制防止杂交种子无限循环，维持种子经济平衡
- 金光变作为例外，奖励追求变异的玩家
- 代数机制增加策略深度：玩家需要权衡是否继续种植高代种子
- 鼓励玩家定期从商店补充基础种子，或通过杂交获得新种子

### 3.8 提前铲除惩罚（杂交撤销机制）

**核心理念**：种植时判定的杂交结果不会立即发放，而是"挂起"直到作物进入第二阶段。如果玩家在萌芽阶段（第一阶段）铲除作物，已判定的杂交会被撤销，不会发放种子。

**机制说明**：
- 种植时判定杂交成功后，杂交结果进入"待发放"状态
- **触发发放条件**：作物进入第二阶段（stageIndex >= 1）后，杂交种子才会实际发放到种子袋
- **铲除惩罚**：如果作物在萌芽阶段（stageIndex = 0）被铲除，已判定的杂交被撤销，不发放种子

**状态流转**：
```
种植 → 判定杂交成功 → [待发放状态]
                         ↓
              收获时：金光变 或 优质 → 发放杂交种子 ✓
                         ↓
              任何阶段铲除 → 撤销杂交（不发放） ✗
```

**数据存储**：

- farm_cell 表新增 `pending_hybrid_seed` 字段（记录待发放的杂交种子 itemId）
- 种植时如果杂交判定成功，写入该字段
- 收获时满足条件（金光变或优质），实际发放种子并清空该字段
- 铲除时如果有 `pending_hybrid_seed`，直接清空不发放

**设计说明**：

- 防止玩家"种下→判定杂交→立即铲除"的投机行为
- 增加策略深度：玩家需要决定是否等待作物进入第二阶段
- 萌芽阶段铲除的惩罚是失去杂交种子，但不会失去已种植的作物本身（因为还在萌芽）
- 这个机制鼓励玩家耐心，而不是频繁铲除重置

## 四、变异系统

### 4.1 核心理念

作物成熟时，有小概率发生**随机变异**。变异结果可能是正面的（品阶提升、产量翻倍），也可能是负面的（产量减半）。

**萌芽阶段规则**：萌芽阶段（stageIndex=0）所有变异效果均不生效、不显示，从第二阶段开始生效。

### 4.2 变异类型

**正面变异**（概率 90%）：
- 金光变（gold）：品质提升一档（劣质→普通，普通→优质，优质不变），售价按提升后品质计算。**枯萎后也可留种**（自然掉落 1 颗种子）
- 丰收变（double_yield）：产量 ×2
- 速熟变（speed_ripen）：下次生长周期缩短 30%

**负面变异**（概率 10%）：
- 早衰变（wither_early）：枯萎时间提前 50%
- 歉收变（half_yield）：产量减半

### 4.3 变异触发机制

**触发时机**：种植时判定（与杂交同时）

**触发概率**：
- 基础变异率：5%（可配置）
- 正面变异概率：90%（原中性变异已移除，概率合并到正面）
- 负面变异概率：10%

**变异判定**：
1. 种植时，判定是否发生变异（5% 概率）
2. 如果发生变异，再按概率分布判定变异类型
3. 将变异信息写入 farm_cell.mutated + farm_cell.mutation_type

**变异效果应用**：
- 在收获时根据 mutation_type 调整产出
- 金光变：品质提升一档（劣质→普通，普通→优质，优质不变）
- 丰收变：产量 ×2
- 速熟变：生长周期缩短 30%（提前成熟）
- 早衰变：枯萎时间提前 50%（更早枯萎）
- 歉收变：产量减半

### 4.4 变异触发逻辑

种植作物时，系统执行以下步骤：

1. 判定是否发生变异（5% 概率）
2. 如果发生变异，按概率分布判定变异类型：
   - 正面变异 90%：金光变 / 丰收变 / 速熟变 随机一种
   - 负面变异 10%：早衰变 / 歉收变 随机一种
3. 将变异信息写入格子的 mutated 和 mutation_type 字段
4. 计算实际生长时间（速熟变缩短 30%，萌芽阶段不生效）
5. 计算实际枯萎时间（早衰变提前 50%，萌芽阶段不生效）
6. 收获时根据 mutation_type 调整产出：
   - 金光变：品质提升一档（劣质→普通，普通→优质）
   - 丰收变：产量翻倍
   - 歉收变：产量减半

### 4.5 变异与杂交的关系

**同时判定**：
- 变异和杂交都在种植时判定
- 两者独立，互不影响

**杂交前提条件**：
- 相邻作物必须是**非成熟阶段**（详见 3.3 节）
- 这意味着杂交依赖种植时机的策略布局，而非变异结果

**可以叠加**：
- 一次种植可以同时触发变异 + 杂交
- 变异效果在收获时应用
- 杂交效果是发放种子

### 4.6 品质判定与种子返还

**核心理念**：收获产出分三档品质（优质 / 普通 / 劣质），只有优质品质才有概率获得可种植种子，劣质有产量惩罚。

**种子返还规则（含代数限制）**：
- 第 0~3 代种子：正常按品质/变异判定返还
- **第 4 代及以上**：除非金光变，否则枯萎时**颗粒无收**（不返还种子）
- 金光变例外：任何代数均可留种

**品质判定**：
- 收获时按概率分布判定品质：
  - 优质（HQ）：20%
  - 普通（Normal）：70%
  - 劣质（LQ）：10%
- 品质判定独立于变异判定，两者可同时触发
- 变异中的"金光变"可将品质提升一档（劣质→普通，普通→优质，优质不变）

**种子产出条件**（最多产出 1 颗，不叠加）：
- **金光变**：必然产出 1 颗种子（不受品质影响）
- **优质（HQ）**：必然产出 1 颗种子（非金光变时）
- **普通/劣质**：不产出种子

**各品质效果**：

| 品质 | 售价 | 产量 | 产出种子 | UI 标识 |
|------|------|------|---------|---------|
| 优质（HQ） | ×2 | 正常 | 必然产 1 颗 | 金色边框 + "优质"标签 |
| 普通（Normal） | ×1 | 正常 | 不产出 | 无特殊标识 |
| 劣质（LQ） | ×0.5 | ×0.5 | 不产出 | 灰色边框 + "劣质"标签 |

**种子经济循环**：
- 种植消耗种子（从商店购买 / 杂交获得 / 收获产出获得）
- 收获时优质或金光变必然返还种子
- **代数限制**：第 4 代及以上种子，除非金光变，否则枯萎时颗粒无收
- 劣质产出有双重惩罚（产量减半 + 售价减半），玩家需要铲除或接受损失
- 金光变战略价值：必然留种 + 任何代数均可留种 + 品质提升

**设计说明**：
- 三档品质增加随机性和策略深度
- 劣质 10% 概率足够让玩家"警惕"，但不至于沮丧
- 金光变保证留种，让负面变异也有补救空间
- 优质也保证留种，激励玩家追求高品质
- 种子不无限产出（普通/劣质不产种），避免经济通胀

### 4.7 花卉类收获机制（harvestableStage / seedableStage）

**核心理念**：不同作物类型可以配置不同的"可收获阶段"和"可留种阶段"，增加策略博弈。

**配置字段**（crops.json）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `harvestableStage` | number | 可收获的阶段索引（0-based）。到达此阶段后即可收获。默认/未设置时使用最后一阶段。 |
| `seedableStage` | number \| null | 可产出种子的阶段索引（0-based）。只有在此阶段或之后收获才能尝试产种子。null 表示任何可收获阶段均可（由 seedFromYield 控制）。 |

**普通作物示例**（五行灵根）：
```json
{
  "stageLabels": ["灵芽", "金苗", "成熟"],
  "growthStageMinutes": [10, 15, 20],
  // 未配置 harvestableStage → 默认最后一阶段（成熟）可收获
  // 未配置 seedableStage → 任何可收获阶段均可产种子
}
```

**花卉类示例**（牵牛花）：
```json
{
  "stageLabels": ["萌芽", "开花", "结果"],
  "growthStageMinutes": [5, 10, 10],
  "harvestableStage": 1,   // 开花即可收获
  "seedableStage": 2,      // 结果才能留种
  "witherAfterMinutes": 10 // 结果后很快枯萎
}
```

**博弈点**：

| 策略 | 时机 | 优点 | 缺点 |
|------|------|------|------|
| 提前收获 | 开花阶段 | 速度快、风险低（不会被枯萎） | 产量低、无种子 |
| 延迟收获 | 结果阶段 | 产量高、可留种 | 可能被枯萎 |

**枯萎时间计算**：
- 枯萎等待时间从可收获阶段结束后开始计算
- 花卉类 `witherAfterMinutes` 通常设置较短（如 10 分钟），增加博弈压力

### 4.8 枯萎处理机制

**核心理念**：模拟自然规律，作物枯萎后通常颗粒无收，但金光变作物有几率留下种子。

**枯萎时的处理**：

| 情况 | 灵材产出 | 种子产出 | 说明 |
|------|----------|----------|------|
| 普通作物枯萎 | 无 | 无 | 颗粒无收 |
| 金光变作物枯萎 | 无 | 1 颗种子 | 自然掉落的种子，不依赖品质判定 |

**设计理由**：
- 金光变作为正面变异，给予"枯萎保险"，降低玩家损失
- 枯萎留种不产生灵材，保持枯萎的惩罚性质
- 种子不带变异遗传（枯萎后种子回归普通）

## 五、变异遗传系统

### 5.1 核心理念

变异作物收获的种子可以保留变异特性，种下后长出的作物会继承变异类型，形成"变异品系"。

### 5.2 遗传机制

**遗传触发条件**：
- 变异作物收获时，如果产出种子（优质品质 30% 概率），种子有概率继承变异
- 遗传概率：50%（可配置）
- 非变异作物产出的种子不会有变异

**遗传效果**：
- 变异种子种下后，长出的作物自动携带相同的变异类型
- 不需要再次判定变异，直接应用变异效果
- 收获时仍然可以再次触发变异（产生新的变异或保持原有变异）

**遗传代数**：
- 无限代遗传：变异种子产出的种子仍然可以遗传变异
- 每代都有 50% 概率丢失变异（种子不带变异）
- 形成"变异品系"的概念：玩家需要筛选和保持优质品系

### 5.3 遗传判定逻辑

变异作物收获时，如果产出种子：
1. 判定是否遗传变异（50% 概率）
2. 如果遗传，种子标记为"变异种子"（seed_mutation_type 字段）
3. 如果不遗传，种子是普通种子

种植变异种子时：
1. 读取种子的 seed_mutation_type
2. 种植后，格子的作物自动携带该变异
3. 不需要重新判定变异

### 5.4 种子数据结构

种子袋需要区分普通种子和变异种子：
- 普通灵稻种子：10 颗
- 变异灵稻种子（金光变）：2 颗
- 变异灵稻种子（丰收变）：1 颗

**数据库字段**：
- `farm_seed_inventory` 表新增：`mutation_type`（文本，NULL 表示普通种子）

## 六、灵田装饰系统

### 6.1 核心理念

玩家可以在灵田网格中放置装饰物，装饰物影响相邻格子的生长速度或产量，增加布局策略。

### 6.2 装饰物类型

**灵泉**：
- 效果：相邻格子生长速度 +20%
- 范围：八方向相邻
- 获取方式：商店购买 / 任务奖励
- 占用：占据一个格子，不能种植

**灵石**：
- 效果：相邻格子产量 +10%
- 范围：八方向相邻
- 获取方式：商店购买 / 任务奖励
- 占用：占据一个格子，不能种植

**聚灵阵**：
- 效果：相邻格子变异概率 +5%（基础 5% → 10%）
- 范围：八方向相邻
- 获取方式：高级任务奖励 / 活动奖励
- 占用：占据一个格子，不能种植

### 6.3 装饰物放置规则

**放置限制**：
- 装饰物占据一个格子，该格子不能种植作物
- 每个格子只能放置一个装饰物
- 装饰物可以移除（返还 50% 成本）

**效果叠加**：
- 多个装饰物效果可以叠加
- 例如：一个格子相邻两个灵泉，生长速度 +40%
- 效果上限：生长速度 +100%、产量 +50%、变异概率 +15%

**相邻判定**：
- 装饰物的"相邻"也是八方向
- 装饰物之间没有互相影响，只影响作物格子

### 6.4 装饰物数据结构

**farm_decoration 表**：
- id：主键
- character_id：玩家标识
- row：行号
- col：列号
- decoration_type：装饰物类型（'spring' / 'stone' / 'array'）
- placed_at：放置时间

唯一约束：(character_id, row, col)

**说明**：装饰物使用独立表管理，farm_cell 表不需要新增字段。查询时通过 (row, col) 关联判断格子是否有装饰物。

### 6.5 装饰物效果应用

**生长速度加成**：
- 在 computeCropState 时，检查相邻格子是否有灵泉
- 计算灵泉数量，应用生长速度加成

**产量加成**：
- 在收获时，检查相邻格子是否有灵石
- 计算灵石数量，应用产量加成

**变异概率加成**：
- 在收获时判定变异前，检查相邻格子是否有聚灵阵
- 计算聚灵阵数量，应用变异概率加成

## 八、后端服务变更

### 8.1 服务拆分

- **farmService.ts**：改造，操作对象从 plot 改为 cell
- **farmHybridService.ts**：改造，从手动配方改为自动触发
- **farmMutationService.ts**：新增，变异判定与效果应用
- **farmGridService.ts**：新增，网格管理、相邻计算、解锁逻辑

### 8.2 核心 API 变更

**旧 API**：
- POST /api/farm/plant：参数 { slotIndex, itemId }
- POST /api/farm/harvest：参数 { slotIndex }
- POST /api/farm/unlock：参数 { slotIndex }
- POST /api/farm/upgrade：参数 { slotIndex }

**新 API**：
- POST /api/farm/plant：参数 { row, col, itemId }
- POST /api/farm/harvest：参数 { row, col }
- POST /api/farm/unlockCell：参数 { row, col }，解锁单个格子
- POST /api/farm/expandGrid：参数 { }，扩展行数（4→5→6）

**新增 API**：
- GET /api/farm/hybridLog：查询杂交历史记录
- GET /api/farm/mutationLog：查询变异历史记录

### 8.3 种植流程

种植作物时，系统执行以下步骤：

1. 校验种子、格子、灵田等级等条件
2. 如果种子是变异种子，读取 mutation_type
3. 如果不是变异种子，判定是否发生变异（5% 概率），确定 mutation_type
4. 检查新种作物是否是**基础作物**（有杂交配方）
5. 如果是基础作物，获取四方向相邻格子，筛选非成熟作物
6. 收集相邻作物的 crop_id 集合，按 3.4 节逻辑匹配杂交配方
7. 如果触发杂交，记录待发放杂交种子（pending_hybrid_seed）
8. 扣减种子，更新格子的 crop_id、planted_at、mutated、mutation_type
9. 计算实际生长时间（考虑速熟变效果和装饰物加成）
10. 计算实际枯萎时间（考虑早衰变效果）
11. 返回种植结果（含是否触发杂交、变异类型）

### 8.4 收获流程

收获作物时，系统执行以下步骤：

1. 锁定格子（SELECT FOR UPDATE）
2. 计算生长状态，确认已成熟（考虑速熟变效果）
3. 检查是否枯萎（考虑早衰变效果），如果枯萎则清理格子
4. 读取格子的 mutation_type（种植时已判定）
5. 判定品质：按 4.6 节逻辑执行（优质 20% / 普通 70% / 劣质 10%）
6. 应用变异效果：金光变将品质提升一档（劣质→普通，普通→优质）
7. 计算产量：根据作物配置、mutation_type、quality 调整（劣质产量减半，歉收变产量减半，丰收变产量翻倍）
8. 如果品质为优质，判定是否产出种子（30% 概率）
9. 如果产出种子：
   - 检查作物的 seed_from_yield 字段
   - 如果 seed_from_yield=true，从产量中扣除 1 颗种子
   - 如果 seed_from_yield=false，产量不变，种子额外产出
   - 如果作物有变异，判定是否遗传变异给种子（50% 概率）
10. 发放收获物到灵材仓库（标记品质）
11. 如果产出种子，发放到种子袋（标记变异类型）
12. 清空格子（crop_id、planted_at、mutated、mutation_type）
13. 返回收获结果（产量、品质、是否产出种子、变异类型、种子产出模式）

## 九、经济系统

### 9.1 种子与产物的价格关系

**核心原则**：种子售价 > 单个产物售价，确保经济平衡。

**设计理由**：
- 种子是投入成本，产物是产出收益
- 如果种子便宜产物贵，玩家可以无限套利
- 种子价格高迫使玩家谨慎选择种植策略，追求优质产出

**示例**：
- 灵稻种子：10 灵石/颗
- 灵稻产物：单株产量 160 颗（普通品质）
- 如果 1000 颗灵稻产物售价 100 灵石，那么单株 160 颗 = 16 灵石
- 玩家收益：16 - 10 = 6 灵石/株（普通品质）
- 优质品质：160 颗 × 2（售价翻倍）= 32 灵石，收益 22 灵石/株
- 劣质品质：160 颗 × 0.5（产量减半）× 0.5（售价减半）= 40 颗 × 0.5 = 20 颗 = 2 灵石，收益 -8 灵石/株（亏损）

### 9.2 产物交易单位

**系统收购规则**：
- 产物按 1000 颗 = 1 单位进行交易
- 商店界面显示"单位售价"（如 100 灵石/单位）
- 玩家出售时，系统自动计算可出售的单位数（向下取整）
- 不足 1000 颗的余数保留在背包中

**示例**：
- 背包有 2500 颗普通灵稻
- 可出售 2 单位（2000 颗），获得 200 灵石
- 剩余 500 颗保留在背包

### 9.3 作物单位与种子产出模式

**种子与产物的单位**：
- 每种作物的种子和产物都有独立的单位标识
- 种子单位（seedUnit）：如"颗"、"粒"
- 产物单位（harvestUnit）：如"颗"、"朵"、"株"、"片"

**示例**：
- 灵稻：种子"颗"，产物"颗"（seedUnit="颗"，harvestUnit="颗"）
- 焰心莲：种子"颗"，产物"朵"（seedUnit="颗"，harvestUnit="朵"）
- 青木灵草：种子"粒"，产物"株"（seedUnit="粒"，harvestUnit="株"）

**种子产出模式**：
- 从产量扣除（seedFromYield=true）：产出种子后，产物数量减少
  - 例：灵稻产量 160 颗，HQ 产出 1 颗种子后，产物变为 159 颗
  - 适用：种子和产物是同一物质的作物（如灵稻的种子就是灵稻本身）
- 不从产量扣除（seedFromYield=false）：产出种子后，产物数量不变
  - 例：焰心莲产量 10 朵，HQ 产出 1 颗种子后，产物仍是 10 朵
  - 适用：种子和产物是不同物质的作物（如焰心莲的种子是"核"，产物是"花"）

**设计理由**：
- 单位差异化增加世界观丰富度（不同作物有不同的计量方式）
- 两种产出模式反映不同的生物逻辑：
  - "从产量扣除"：种子就是果实本身，种下去的是收获的作物
  - "不从产量扣除"：种子是额外的繁殖材料，与产物独立

**数据库字段**：
- `crop_config` 表新增：
  - `seed_unit`：种子单位（文本，如"颗"）
  - `harvest_unit`：产物单位（文本，如"颗"、"朵"）
  - `seed_from_yield`：是否从产量扣除种子（布尔，默认 true）

**UI 显示**：
- 种子袋显示：灵稻种子 10 颗、焰心莲种子 3 颗
- 灵材仓库显示：灵稻 1500 颗、焰心莲 8 朵
- 收获提示：产出灵稻 160 颗 + 种子 1 颗（产量扣除）/ 产出焰心莲 10 朵 + 种子 1 颗（额外产出）

### 9.4 作物背包按品质分别存储

**背包结构**：
- 每种作物按品质分别计数：普通 / 优质 / 劣质
- 出售时只能按品质单独出售，不能混合
- UI 显示三种品质的数量，分别操作

**设计理由**：
- 优质产物售价翻倍，不能与普通混合出售（避免玩家混淆）
- 劣质产物售价减半，需要单独标识
- 玩家可以选择时机分别出售不同品质

**示例**：
- 灵稻背包：普通 1500 颗 / 优质 300 颗 / 劣质 200 颗
- 可出售：普通 1 单位（150 灵石）+ 优质 0 单位（300 颗不足 1 单位）+ 劣质 0 单位
- 或者等待积累更多优质后再出售

## 十、前端变更

### 10.1 网格渲染

前端使用 antd `Row` + `Col` 栅格系统渲染灵田网格（禁止自行编写 CSS Grid）：

- 每个格子使用 antd `Card` 组件（size="small"），内嵌 `Progress` 展示生长进度
- 固定 4 列，行数由 `maxRow` 决定（4/5/6），通过 `Row` 分行渲染
- 格子按 `(row, col)` 排序，从左到右、从上到下排列
- 每个格子显示：作物名称（`Tag`）、生长进度（`Progress`）、变异标识（`Tag` 颜色区分）、品质标签（`Tag`）
- 锁定格子显示 `LockOutlined` 图标 + 解锁按钮
- 移动端 4 列紧凑布局（每列 span=6），桌面端可适当加大格子尺寸

### 10.2 相邻高亮

当玩家选中一个格子时，高亮其四方向相邻格子（用于杂交提示）：

- 前端根据选中的 `(row, col)` 计算相邻位置列表
- 渲染时，对每个格子判断是否在相邻列表中
- 相邻格子添加高亮边框样式
- 帮助玩家直观理解杂交范围

### 10.3 杂交/变异/品质提示

- 作物成熟时，如果四方向相邻格子有不同灵根作物，显示"可杂交"提示图标
- 变异的作物显示特殊边框或光效，区分变异类型
- 鼠标悬浮或点击时显示详细信息（变异类型、杂交配方等）

### 10.4 前端开发规范

#### 10.4.1 布局优先使用 antd 组件

**禁止过度 div + css**，必须优先使用 antd 已有组件进行布局：

- 网格布局优先使用 antd `Row` + `Col` 栅格系统，而非自行编写 `display: grid` CSS
- 间距、分隔优先使用 antd `Flex`（gap）、`Divider`、`Space`
- 信息展示优先使用 antd `Descriptions`、`Statistic`、`Tag`
- 弹窗交互使用 antd `Modal`，不使用原生 div 手搓弹窗
- 表单交互使用 antd `Form`、`InputNumber`、`Select`、`Button`
- 进度展示使用 antd `Progress`
- 空状态使用 antd `Empty`
- 提示反馈使用 antd `message` / `notification` / `Tooltip`

只有在 antd 组件确实无法满足需求时，才允许使用自定义 CSS（且必须同时适配桌面端/移动端、浅色/深色主题）。

#### 10.4.2 切换 Tab 触发接口防重

灵田页面包含多个 Tab（灵田、种子商店、灵材仓库、杂交日志等），切换 Tab 时会触发对应的数据加载接口。

**必须遵守防重规范**（参见 CLAUDE.md 请求去重设计规范）：

- 使用 `RequestDedup`（in-flight 守卫，不用 TTL）进行防重
- `dedup.enter(key)` 必须在设置 loading 之前调用
- `dedup.complete(key)` 必须放在 finally 中
- 同一个 Tab 快速来回切换，不会发起重复请求
- Tab 切换后的首次加载走正常防重流程，被拦截时不显示 loading（避免闪烁）

## 十二、关键设计决策

### 12.1 为什么扩展是加行不是加列？

- 玩家群体移动端为主，竖屏布局下 4 列已接近屏幕宽度极限
- 向下延伸（加行）符合移动端纵向滚动习惯，不需要横向滚动
- PC 端同样统一加行，保持多端一致的交互体验
- 4 列在移动端可以每列占 25% 宽度（span=6），格子尺寸足够触控

### 12.2 为什么杂交产物发放种子而不是自动种植？

- 发放种子简单可控，不干扰现有网格状态
- 给玩家选择权，可以选择最佳位置种植
- 避免"目标格子已有作物"的复杂处理

### 12.3 为什么变异率设为 5%？

- 太低（<1%）：玩家感知不到，失去乐趣
- 太高（>10%）：变异泛滥，失去稀缺感
- 5% 是一个平衡点：平均每 20 次收获触发 1 次，既有期待感又不泛滥

### 12.4 为什么负面变异概率只有 10%？

- 负面体验会放大玩家的不满
- 10% 的负面率（即 0.5% 总概率）足够让玩家"小心"，但不至于"沮丧"
- 可以通过道具/技能降低负面变异率，作为成长点

## 十六、V3 等级系统重构

> V3 将原有的单一"灵田等级"拆分为**等级（Level）**和**等阶（Tier）**两个独立维度，并引入**开垦机制**。

### 16.1 核心变化概览

| 维度 | V2 | V3 |
| ---- | -- | -- |
| 等级概念 | 灵田等级 1-3（对应 4×4、5×4、6×4）| 等级（Level）0-100 + 等阶（Tier）黄/玄/地/天 |
| 升级方式 | 消耗息壤 + 经验手动突破 | 等级自动升级，等阶手动突破 |
| 经验获取 | 每种作物配置不同 expGain | 统一：收获 +1，枯萎且无种子 +0 |
| 解锁扩展 | 灵田等级提升 → 解锁新行 | 等阶限制种子种植，扩展格子需付费 |
| 初始灵田 | 首次访问自动创建 | 需要支付灵石开垦 |

### 16.2 等级系统（Level）

#### 16.2.1 经验获取

| 操作 | 经验 |
| ---- | ---- |
| 成功收获作物 | +1 |
| 枯萎且无种子掉落 | +0 |
| 枯萎但有种子掉落（金光变）| +1 |

#### 16.2.2 升级机制

- **升级方式**：自动升级（达到阈值自动升）
- **等级上限**：100 级
- **经验公式**：`100 + 50 * (level - 1)`（线性递增）

| 等级 | 所需经验 |
| ---- | -------- |
| 1 → 2 | 100 |
| 2 → 3 | 150 |
| 3 → 4 | 200 |
| ... | ... |
| 99 → 100 | 5050 |

#### 16.2.3 等级效果

- **正向变异概率加成**：每级 +0.1%，最高 +10%（100 级）
- **负面变异概率抑制**：每级 -0.1%，最高 -10%（100 级）

### 16.3 等阶系统（Tier）

#### 16.3.1 等阶定义

| 等阶 | 名称 | 显示名 | 最小等级 | 息壤消耗（累计）|
| ---- | ---- | ------ | -------- | --------------- |
| 1 | 黄级 | 黄级（凡土）| 0 | 1 |
| 2 | 玄级 | 玄级（灵壤）| 25 | 3 |
| 3 | 地级 | 地级（仙壤）| 50 | 8 |
| 4 | 天级 | 天级（神壤）| 75 | 20 |

**息壤消耗说明**：`xiRangCost` 是从黄级累计的每格息壤消耗量，用于计算等阶突破和格子扩展费用。

#### 16.3.2 等阶作用

- **限制种子种植**：种子有 `requiredTier` 字段，玩家等阶必须 ≥ 种子等阶才能种植
- **当前测试种子**：全部为黄级（requiredTier = 1）

#### 16.3.3 等阶突破

**突破条件**：
1. 达到目标等阶的最小等级要求
2. 消耗灵石购买息壤（费用 = 当前格子数 × 目标等阶 xiRangCost × 息壤单价）

**示例**：玩家从黄级突破到玄级，当前有 16 格，息壤单价 200：
- 费用 = 16 × 3 × 200 = 9600 灵石

### 16.4 开垦机制

#### 16.4.1 核心规则

- 玩家首次进入灵田时，**不会自动创建灵田**
- 需要点击"开垦灵田"按钮，确认支付费用后才能开垦
- 首次开垦必须开垦 **16 格**（4×4）

#### 16.4.2 费用计算

| 操作 | 费用公式 |
| ---- | -------- |
| 首次开垦（16 格）| 16 × (1000 灵石 + 1 息壤 × 单价) |
| 后续扩展（1 格）| 1000 灵石 + 当前等阶 xiRangCost × 息壤单价 |

**示例**（假设息壤单价 200）：
- 首次开垦（黄级，16 格）：16 × (1000 + 1 × 200) = 19200 灵石
- 玄级时扩展 1 格：1000 + 3 × 200 = 1600 灵石
- 天级时扩展 1 格：1000 + 20 × 200 = 5000 灵石

#### 16.4.3 开垦后奖励

- 创建 `farm_profile` 记录
- 创建 16 个已解锁的格子（4×4）
- 发放初始种子（配置在 plots.json）

### 16.5 息壤经济

#### 16.5.1 息壤本质

**重要**：目前没有仓库系统，息壤**不是实物道具**，而是后端按公式计算出来的**数值**，仅用于前端展示。

- 玩家不需要先购买息壤再使用
- 息壤数量 = 后端根据操作类型和当前等阶计算得出
- 前端显示"需要 X 息壤"，实际只扣除灵石

#### 16.5.2 息壤计算公式

| 操作 | 息壤计算公式 | 灵石计算公式 |
| ---- | ------------ | ------------ |
| 首次开垦（16 格）| 16 × 1 = 16 | 16 × 1000 = 16000 |
| 等阶突破 | 当前格子数 × 目标等阶 xiRangCost | 0（息壤费用已包含在灵石中）|
| 扩展格子 | 当前等阶 xiRangCost | 1000 |

**实际扣除**：后端只扣除灵石，息壤数量用于前端展示。

#### 16.5.3 息壤单价

- **全局统一配置**：在 plots.json 中配置 `xiRang.pricePerUnit`
- **用于前端展示**：息壤总价值 = 息壤数量 × 单价
- **不是每个等阶单独配置**

### 16.10 设计理由

#### 16.10.1 为什么拆分等级和等阶？

- **等级**：反映玩家的辛勤程度（收获次数），自动升级无消耗
- **等阶**：反映玩家的实力阶段，限制能种植的作物种类
- 分离后，玩家可以自由决定何时突破等阶（需要消耗资源）

#### 16.10.2 为什么开垦需要付费？

- 增加沉没成本，提高玩家留存
- 避免玩家随意创建灵田又放弃
- 与经济系统联动，灵石消耗有去处

#### 16.10.3 为什么格子扩展费用递增？

- 鼓励玩家在低等阶时规划布局
- 高等阶扩展成本高，但收益也高（可种植高级作物）
- 形成经济压力，玩家需要权衡扩展时机

## 十七、活动日志系统

> 记录玩家在灵田中的所有关键操作，便于回顾种植历史和追溯问题。

### 17.1 日志类型

| activity_type | 触发时机 | metadata 字段 |
|---------------|----------|---------------|
| `plant` | 播种成功 | `generation`, `mutationType`, `hybridTriggered` |
| `harvest` | 收获成功 | `quantity`, `quality`, `seedProduced` |
| `remove` | 铲除成功 | `hybridRevoked` |
| `wither` | 枯萎结算 | `seedDropped` |
| `hybrid` | 杂交判定成功 | `recipeName`, `resultSeedName` |
| `mutation` | 变异判定成功 | `mutationType` |

### 17.2 数据库表

```prisma
model farm_activity_log {
  id              BigInt   @id @default(autoincrement())
  character_id    Int
  activity_type   String   @db.VarChar(20)
  row             Int      @db.SmallInt
  col             Int      @db.SmallInt
  crop_id         String?  @db.VarChar(64)
  metadata        Json     @db.JsonB
  created_at      DateTime @default(now()) @db.Timestamp(6)

  character       characters @relation(...)
}
```

### 17.3 API

```
GET /api/farm/log?limit=50
```

返回最近 50 条日志（倒序）。

### 17.4 前端展示

使用 antd Table 组件，三列布局：

| 列 | 宽度 | 说明 |
|----|------|------|
| 时间 | 120px | `MM-DD HH:mm` 格式（Asia/Shanghai 时区） |
| 类型 | 80px | Tag 标签，颜色区分活动类型 |
| 详情 | 自适应 | 纯文本，含作物名、位置、关键参数 |
